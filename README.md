# MariaDB Snapshot

> **Developed with OpenAI Codex.** 이 프로젝트는 사용자가 작성한 요구사항을 바탕으로 OpenAI Codex를 활용하여 코드 구현, UI 개선, 테스트 및 문서를 작성했습니다.

선택한 MariaDB 테이블을 기준일별 분석 스냅샷으로 복사하는 로컬 도구입니다. Streamlit UI, 별도 Python worker, SQLite 실행 이력으로 구성합니다. 운영 원본에는 읽기와 연결 세션 설정만 수행하며, 모든 선택 테이블을 검증한 뒤 대상에서 한 번에 공개합니다.

## 1. 실행 전에 준비할 것

- **Python 3.11 이상**: 앱을 실행할 PC에 설치합니다.
- **원본 MariaDB**: 복사할 테이블과 읽기 전용 계정을 준비합니다.
- **대상 MariaDB**: 저장할 DB/schema와 테이블 생성·적재 권한이 있는 별도 계정을 준비합니다.
- **연결 정보**: 각 DB의 호스트, 포트, DB명, 사용자, 비밀번호가 필요합니다.
- **디스크 공간**: 원본에서 읽은 데이터를 중간 파일로 저장할 공간이 필요합니다.

이 앱은 MariaDB 서버나 DB/schema 자체를 설치·생성하지 않습니다. 대상 DB/schema는 미리 준비해야 하며, 그 안의 **스냅샷 테이블은 전체 실행 시 자동 생성**합니다. 대상은 로컬 또는 원격 MariaDB를 사용할 수 있습니다. 원본과 대상이 같은 서버의 같은 DB/schema이면 차단합니다.

기존 MariaDB에 연결해 사용하는 경우 **Docker는 필요하지 않습니다**. 아래의 개발용 DB 통합 테스트에만 Docker를 사용합니다. 실제 검증 환경은 macOS / Python 3.12 / MariaDB 11.4이며, Windows 실기기 검증 여부는 [검증 기록](VALIDATION.md)을 참고하세요.

## 2. 로컬 실행

### Windows: 시작 파일 실행

1. 프로젝트 폴더를 PC에 복사합니다.
2. 폴더 안의 **`start-windows.bat`를 더블클릭**합니다.
3. 처음 실행하면 `.venv` 가상환경과 필요한 패키지를 설치합니다. 최초 패키지 설치에는 인터넷 연결이 필요합니다.
4. 실행 창에 주소가 표시되면 브라우저에서 **[http://127.0.0.1:8501](http://127.0.0.1:8501)**을 엽니다. 브라우저는 자동으로 열리지 않을 수 있습니다.
5. 앱을 사용하는 동안 실행 창을 유지합니다.

PowerShell에서 실행하려면 프로젝트 폴더로 이동한 뒤 아래 명령을 사용합니다. `C:\work\tool-db-table-snapshot`은 예시이므로 실제 폴더 경로로 바꾸세요.

```powershell
cd "C:\work\tool-db-table-snapshot"
.\start-windows.bat
```

시작 파일 대신 직접 설치·실행하려면 다음 명령을 순서대로 입력합니다.

```powershell
py -3 --version
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

별도의 가상환경 활성화 명령은 필요 없습니다. `py -3 --version` 결과가 3.11 이상인지 확인하세요.

### macOS: 터미널에서 실행

프로젝트 폴더로 이동한 뒤 다음 명령으로 실행합니다. 아래 경로는 예시입니다.

```sh
cd "$HOME/Projects/tool-db-table-snapshot"
./start-macos.sh
```

다른 위치에 복사했다면 `cd` 뒤의 경로를 바꾸세요. 최초 실행 때 가상환경과 패키지를 설치합니다. 실행 후 **[http://127.0.0.1:8501](http://127.0.0.1:8501)**을 엽니다.

직접 설치·실행하려면 다음 명령을 사용합니다.

```sh
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1
```

### 다음부터 실행할 때

Windows는 `start-windows.bat`, macOS는 `./start-macos.sh`를 다시 실행하면 됩니다. 기존 가상환경을 재사용합니다. 설정과 실행 이력도 같은 저장 경로에서 불러옵니다.

시작 스크립트는 **가상환경이 없는 경우에만** 패키지를 설치합니다. 최초 설치가 중단되었거나 코드를 업데이트해 의존성이 바뀌었다면 해당 OS의 위 명령 중 `python -m pip install -e .`에 해당하는 줄을 다시 실행하세요.

### 종료할 때

1. **5. 결과·복구**에서 실행이 끝났는지 확인합니다. 진행 중이라면 필요에 따라 **복사 취소**를 누르고 결과를 기다립니다.
2. 터미널/실행 창에서 **Ctrl+C**로 Streamlit 서버를 종료합니다.

브라우저만 닫아도 별도 복사 프로세스는 계속 실행됩니다. **Streamlit 서버 종료를 복사 취소 방법으로 사용하지 마세요.** PC 종료·절전 중 실행 지속은 보장하지 않습니다.

## 3. 사용 방법: 화면 순서대로 진행하기

**연결 설정 → 복사 작업 → 소량 테스트 → 전체 실행 → 결과·복구** 순서입니다. 사이드 메뉴 또는 화면의 **다음** 버튼으로 이동합니다. 실행 중인 작업이 있으면 새로 접속해도 진행 상황을 다시 확인할 수 있습니다.

### 1단계 · 연결 설정

먼저 원본 DB, 다음으로 대상 DB를 등록합니다.

1. **① 원본 DB**를 선택합니다.
2. 연결 이름, 호스트, 포트, DB명, 사용자, 비밀번호를 입력합니다.
3. 인증서가 필요한 환경이면 **보안 연결 · TLS (필요한 경우)**를 열어 설정합니다.
4. **연결 저장**을 누른 뒤 **접속 확인**으로 연결과 읽기 가능 여부를 확인합니다.
5. **다음 · 대상 DB 등록하기** 또는 **② 대상 DB**를 선택하여 대상 연결을 같은 방식으로 등록하고 접속을 확인합니다.
6. 두 연결을 등록했으면 **다음 · 복사 작업 만들기**를 누릅니다.

| 입력 항목 | 입력할 내용 |
|---|---|
| 연결 이름 | 화면에서 구분할 이름. 예: `운영 원본`, `로컬 분석 DB` |
| 호스트 | DB 서버 주소. 앱과 같은 PC에 설치한 대상 DB라면 `localhost` |
| 포트 | 해당 MariaDB가 사용하는 포트. 기본 입력값은 `3306` |
| DB명 | 미리 만들어진 DB/schema 이름 |
| 사용자 | 원본은 읽기 전용 계정, 대상은 생성·적재 권한 계정 |
| 비밀번호 | 해당 계정의 접속 비밀번호 |

**비밀번호 저장**을 선택하면 이 PC의 안전한 OS 자격 증명 저장소를 사용합니다. 선택하지 않으면 현재 브라우저 세션에서만 사용하며, 새 세션에서는 필요한 화면에 표시되는 비밀번호 입력란이나 사이드바 **비밀번호 관리**에서 다시 입력합니다. 기존 연결을 편집할 때 비밀번호를 비워두면 기존 자격 증명을 사용합니다.

연결 수정은 **연결 선택**에서 기존 연결을 고른 뒤 저장합니다. 삭제와 설정 파일 가져오기/내보내기는 접힌 영역에 있습니다. 내보낸 파일에는 비밀번호가 포함되지 않습니다.

### 2단계 · 복사 작업

작업 하나는 원본 테이블 하나와 대상 테이블 하나의 매핑입니다.

1. **① 읽을 원본 DB**를 고릅니다.
2. **원본 테이블 목록 가져오기**를 누릅니다. 목록을 가져오지 않고 테이블명을 직접 입력할 수도 있습니다.
3. **② 원본 테이블**을 고릅니다.
4. **③ 저장할 대상 DB**를 고릅니다.
5. **④ 대상 테이블 이름**을 입력합니다. 공란이면 원본 테이블명을 사용합니다.
6. **작업 이름 (선택)**을 입력합니다. 공란이면 원본 테이블명을 사용합니다.
7. **복사 작업 저장**을 누릅니다.
8. 필요한 테이블마다 작업을 추가한 뒤 **다음 · 소량 테스트**를 누릅니다.

예를 들어 원본 `orders`를 대상 `orders_snapshot`으로 보관하려면 각각 해당 이름을 입력합니다. 원본에 `snapshot_date`가 이미 있으면 실행을 차단합니다. 대상 테이블명에 `_snapshot_` 접두사는 사용할 수 없습니다.

기본 읽기 방식은 **키 기준으로 나누어 읽기**, 배치당 **1,000행**, 배치 사이 **300ms 대기**입니다. 변경하려면 **읽기 방식과 부하 조절**을 엽니다. PK나 적합한 NOT NULL 유일 키가 없다는 오류가 나오면 **한 번에 연결하여 조금씩 읽기 (키가 없을 때)**를 선택하세요. 이 스트리밍 방식에는 배치 대기를 적용하지 않습니다.

기존 작업은 **작업 선택**에서 불러와 수정합니다. 복제·삭제와 해당 작업의 실행 이력도 같은 화면에서 확인할 수 있습니다. 작업을 선택하거나 저장하는 것만으로 복사를 시작하지 않습니다.

### 3단계 · 소량 테스트

1. **실행할 작업**을 선택합니다. 선택한 순서대로 처리합니다.
2. 처음에는 **100행 (권장 시작)**을 선택합니다. 이후 1,000행 또는 직접 입력으로 늘릴 수 있습니다.
3. **기준일**을 확인합니다.
4. 필요하면 **중간 파일 저장 위치**에서 폴더를 바꾸거나 여유 공간을 확인합니다.
5. 저장하지 않은 비밀번호 입력란이 나타나면 입력합니다.
6. **N개 작업 테스트 시작**을 누릅니다. 자동으로 **5. 결과·복구**로 이동합니다.
7. 테스트가 완료되면 **다음 · 같은 작업 전체 실행**을 누릅니다. 선택 작업과 기준일을 이어서 사용합니다.

테스트 행 수는 **각 작업에 적용**합니다. 작업 3개에 100행을 선택하면 테이블마다 최대 100행씩 읽습니다. 원본이 더 작거나 비어 있으면 그만큼만 읽습니다.

테스트는 원본 추출, 중간 파일 저장, 대상 임시 적재, 검증까지 수행하지만 **정식 스냅샷을 생성하거나 교체하지 않습니다**. 소량 성공이 전체 데이터의 타입 호환성과 처리 성능까지 보장하지는 않습니다.

### 4단계 · 전체 실행

1. 실행할 작업과 **읽을 위치 → 저장할 위치** 요약을 확인합니다.
2. **기준일**을 선택합니다. 수집 날짜 또는 업무 기준 날짜처럼 데이터를 구분할 날짜이며, 실행 도중 자정을 지나도 바뀌지 않습니다.
3. 현재 설정으로 테스트에 성공하지 않은 작업이 있으면 안내가 표시됩니다. 필요하면 **소량 테스트 먼저 하기**로 돌아갑니다.
4. 비밀번호와 중간 파일 저장 위치를 확인합니다.
5. **N개 작업 전체 실행**을 누릅니다. 진행 화면으로 자동 이동합니다.

한 번에 실행할 작업은 **같은 대상 DB 연결**을 사용해야 합니다. 하나의 앱 저장소에서는 실행 하나만 진행할 수 있습니다.

같은 기준일의 성공 데이터가 이미 있으면 모든 선택 테이블의 검증 후 **그 날짜 전체를 교체**합니다. 원본에서 삭제된 행도 새 스냅샷에서 제거됩니다. 다른 날짜의 데이터는 유지합니다. 복사 도중 원본이 변경될 수 있으므로 원본 갱신이 끝난 시간대에 실행하세요.

### 5단계 · 결과·복구

**확인할 실행**에서 현재 실행이나 과거 이력을 선택합니다. 화면은 약 1초마다 로컬 상태를 갱신합니다.

| 표시 | 의미 |
|---|---|
| 원본 읽기 | 원본 데이터를 읽어 중간 파일에 저장 중 |
| 부하 조절 대기 | 다음 원본 배치를 읽기 전에 대기 중 |
| 대상 임시 적재 | 읽기를 끝낸 파일을 대상의 임시 테이블에 적재 중 |
| 검증 / 검증 완료 | 추출·적재 행 수 등을 확인 중이거나 확인을 마친 상태 |
| 최종 저장 중 | 선택한 모든 테이블을 한 트랜잭션으로 정식 저장 중 |
| 완료 · 소량 테스트 | 테스트 경로가 성공함. 정식 데이터는 변경하지 않음 |
| 완료 · 전체 스냅샷 | 모든 선택 테이블의 검증과 최종 저장이 완료됨 |

**임시 적재율 100%만으로 최종 성공을 판단하지 마세요.** 상단의 완료 표시를 확인해야 합니다. 원본 전체 행 수를 모르는 추출 단계에서는 누적 행 수로 진행을 확인합니다.

- **복사 취소**: 진행 중인 작업에 정상 취소를 요청합니다. DB 요청이 끝날 때까지 지연될 수 있습니다.
- **취소가 오래 걸릴 때 · 강제 중단**: 확인 체크 후 해당 복사 프로세스만 종료합니다. 로컬 종료와 서버 쿼리 종료 확인은 다릅니다.
- **1. 최종 저장 결과 확인**: 최종 저장 도중 연결이 끊겨 성공 여부를 모르는 경우 먼저 누릅니다. 확인될 때까지 새 실행이 차단됩니다.
- **같은 설정으로 다시 시도**: 실패·취소·중단된 실행에서 검증된 완료 파일을 재사용합니다. 완료하지 못한 원본 추출은 처음부터 다시 읽습니다.
- **작업 설정 수정**: 연결된 작업 설정을 바꿔 새 실행을 준비합니다. 기존 실행의 재시도는 그 실행 당시 설정을 사용합니다.
- **로그 확인 / 저장**: 오류만 표시하거나 최근 로그를 파일로 저장합니다.
- **중간 파일 정리 → 이 실행의 중간 파일 정리**: 실패 파일과 임시 적재 테이블을 정리합니다. 정식 스냅샷과 로그는 유지합니다. 완료 파일을 지우면 이후 재시도는 원본부터 다시 읽습니다.

실행별 위치와 읽기 설정은 **실행 설정과 연결 상태**, 속도·생존 신호·읽기 시각은 **상세 진단**에서 확인합니다.

## 4. 설정과 데이터가 저장되는 곳

기본값은 프로젝트 안의 `.snapshot/`입니다.

| 위치 | 내용 |
|---|---|
| `.snapshot/state.sqlite3` | 연결 메타데이터, 작업, 실행 설정 사본, 진행 상태와 이력 |
| `.snapshot/files/<실행 ID>/` | 기본 중간 파일 폴더. 화면에서 다른 위치로 변경 가능 |
| 중간 파일 폴더의 `events.jsonl` | 실행별 로그 |
| OS 자격 증명 저장소 | 저장을 선택한 비밀번호 |
| 대상 MariaDB의 작업별 테이블 | 날짜별 정식 스냅샷 데이터 |

성공하면 중간 데이터 파일을 정리하고 로그와 실행 이력을 남깁니다. 실패 파일은 재시도용으로 보관합니다. `.snapshot/`을 지우면 설정과 실행 이력을 잃으므로 초기화 수단으로 임의 삭제하지 마세요.

설정 저장 위치를 변경하려면 **앱을 시작하기 전에** `SNAPSHOT_HOME`을 지정합니다. 아래 경로는 예시입니다.

Windows PowerShell:

```powershell
$env:SNAPSHOT_HOME = "$env:LOCALAPPDATA\MariaDBSnapshot"
.\start-windows.bat
```

macOS:

```sh
SNAPSHOT_HOME="$HOME/Library/Application Support/MariaDBSnapshot" ./start-macos.sh
```

다른 경로를 지정하면 그곳의 설정을 사용하며, 기존 파일을 자동으로 옮기지는 않습니다. 재실행할 때도 같은 값을 지정하세요. 모든 탭/앱 인스턴스에서 같은 저장 경로를 사용하고, SQLite를 네트워크 공유 폴더에 두지 마세요.

## 구현한 정책

| 항목 | 동작 |
|---|---|
| 원본 읽기 | InnoDB, 테이블 순차 처리, 기본 원본 연결 1개 |
| PK 배치 | PK 또는 전체 컬럼이 NOT NULL인 비접두사 유일 키, 복합 키 사전식 keyset, OFFSET 없음 |
| 초기 설정 | 1,000행 / 쿼리, 완료 후 300ms 대기; 스트리밍에는 대기 미적용 |
| 테스트 | SQL LIMIT 100 / 1,000 / 사용자 지정. 정식 테이블 생성/교체 없음 |
| 타입 보존 | JSONL 타입 태그: NULL, 문자열, Unicode, 개행, Decimal, 날짜/시간, Base64 binary |
| 생성 컬럼 | 원본에서 계산된 값을 일반 컬럼으로 저장 |
| 대상 키 | 원본 PK가 있으면 `(snapshot_date, 원본 PK 전체)`. 없으면 날짜 보조 인덱스 |
| 복제하지 않는 속성 | AUTO_INCREMENT, 원본 UNIQUE/보조 인덱스, FK, CHECK, 트리거, 이벤트, 루틴, 기본값/자동 갱신 |
| 스키마 비교 | 이름/순서/타입/NULL/문자셋/콜레이션/PK/UNIQUE. 불일치 시 실패, 자동 변경 없음 |
| 시간 | Source/Target 연결의 세션 시간대를 UTC로 고정하여 TIMESTAMP 값 보존 |
| 적재 | PyMySQL `executemany` 다중 행 INSERT. 행 수/바이트로 나눈 배치, staging 단위 커밋 |
| 적재 경고 | 각 SQL의 경고를 검사하여 경고도 실패 처리; strict SQL mode |
| 검증 | 파일 SHA256/완료 매니페스트 + 추출/적재/staging 행 수. 전체 값 동일성 보장은 아님 |
| 공개 | 동일 Target 연결의 모든 테이블을 단일 InnoDB 트랜잭션에서 날짜별 DELETE/INSERT + 실행 기록 커밋 |
| 재시도 | 유한 통신 재시도. 추출은 해당 테이블 처음부터, 적재는 staging 재생성 + 검증된 완료 파일 재사용 |
| 취소 | SQLite 취소 플래그; 후속 배치/테이블 중지; 공개 전 취소 시 기존 성공본 보존 |
| 강제 종료 | 확인 체크 후 PID + 생성 시각 + worker 명령의 실행 ID 일치 검사. 해당 프로세스만 종료 |
| 상태 복구 | 프로세스와 SQLite를 재확인. 공개가 불확실하면 대상 advisory lock 획득 후 실행 기록 확인 |
| 상태 갱신 | UI는 약 1초마다 로컬 상태 조회. heartbeat 1초, 일반 진행 카운터 최대 약 4회/초 |
| 보안 | 비밀번호는 OS keyring 또는 세션 메모리. worker에 익명 stdin pipe로 전달. SQL 오류 본문의 데이터는 로그에서 제외 |

`LOAD DATA LOCAL INFILE` 대신 배치 INSERT를 채택했습니다. LOCAL INFILE은 **양쪽 모두 비활성화**하며, 서버 LOCAL 설정이나 파일 전송량에 의존하지 않습니다. 메모리 사용은 전체 테이블이 아니라 읽기 청크(최대 256행), 적재 청크와 개별 값 크기에 영향을 받습니다. 아주 큰 단일 BLOB은 별도 시험이 필요하며, `max_allowed_packet`을 초과하면 실패합니다.

지원 타입은 일반 정수/실수/DECIMAL, BIT, 문자/TEXT, binary/BLOB, DATE/DATETIME/TIMESTAMP/TIME/YEAR, ENUM/SET입니다. 공간 타입 등 알 수 없는 타입은 사전 검사에서 차단합니다. MariaDB JSON은 메타데이터에 나타나는 LONGTEXT와 값을 보존하며 원본 CHECK는 복제하지 않습니다.

## 권한과 운영 경계

원본 계정에는 선택할 테이블의 **SELECT**만 부여합니다. 메타데이터와 서버 식별 정보(`@@hostname`, `@@port`, `@@server_id`, `@@datadir`)를 조회할 수 있어야 합니다. 원본에 DDL/DML, 명시적 잠금, COUNT(*), KILL, 전역 설정 변경을 보내지 않습니다. 드라이버의 문자셋/자동 커밋 설정과 `SET SESSION time_zone`은 사용합니다.

대상에는 전용 분석 schema와 별도 계정을 사용하세요. 해당 schema에 SELECT, INSERT, DELETE, CREATE, DROP, CREATE TEMPORARY TABLES가 필요합니다. 실제 영구 테이블 생성 가능 여부와 인덱스 제한은 실행 사전 준비 단계에서 확인합니다. 대상에 기존 트리거, FK/CHECK 또는 확인 가능한 역방향 FK 참조가 있으면 차단합니다. 운영 schema와 FK로 연결하지 않은 전용 영역을 사용하세요.

서버 식별 정보, DNS/IP, 포트와 schema로 확인 가능한 동일 물리 schema 구성을 차단합니다. 프록시, 라우팅 또는 서버 설정에 따른 모든 별칭을 완전 판별하지는 못하므로 Source와 Target 분리를 운영자가 확인해야 합니다.

- 묶음은 **하나의 Target 연결 프로필/schema**를 사용해야 합니다. 서로 다른 Target을 하나의 실행으로 고르면 차단합니다.
- 배치 쿼리는 서로 다른 시점의 데이터를 읽습니다. 전체 테이블 간 동일 원본 시점 스냅샷은 제공하지 않습니다.
- 기준일은 수집 또는 업무 기준일입니다. 자정을 지나도 변경하지 않습니다. 실제 읽기 시작/종료 시각은 따로 기록합니다.
- DDL은 공개 전에 수행하므로 실패한 최초 실행에 **빈 정식 테이블**이 남을 수 있습니다. 기존 성공 데이터는 공개 전 삭제하지 않습니다.
- 대상 테이블들은 외부 쓰기/DDL 없이 이 도구가 관리해야 합니다. 일관된 조인 분석에는 하나의 읽기 트랜잭션을 사용합니다.
- 원본에 `snapshot_date`가 있으면 차단합니다. `_snapshot_` 접두사는 대상 도구 전용입니다.
- 암호화/TLS는 연결 설정에서 선택합니다. TLS를 켜면 인증서와 호스트 이름을 검증합니다.
- macOS Keychain / Windows Credential Manager를 기본 저장소로 사용합니다. 지원되는 안전한 백엔드가 없으면 저장 없이 입력합니다. 자격 증명 export/import는 하지 않습니다.
- 중간 파일은 원본 데이터입니다. POSIX 파일 권한은 폴더 0700/파일 0600으로 제한합니다. **Windows 폴더 ACL과 디스크 암호화는 운영자가 설정**합니다.
- `SNAPSHOT_HOME`을 달리한 별도 설치 전체에 대한 실행 제한은 제공하지 않습니다. 대상 공개 잠금은 도구 실행 간 공개/복구를 직렬화합니다.

## 취소와 복구

정상 취소는 네트워크 I/O 또는 쿼리 완료/제한 시간까지 지연될 수 있습니다. 기다리는 동안에는 짧은 간격으로 취소를 확인합니다. 취소가 마지막 확인보다 늦게 도착하면 공개 커밋이 먼저 끝나 SUCCESS일 수 있습니다.

강제 중단 후에는 `로컬 종료 완료 / 서버 종료 미확인`을 표시합니다. 프로세스를 죽여도 서버 쿼리의 즉시 종료는 보장하지 않습니다. DBA 예외 KILL 경로는 이 버전에 구현하지 않았습니다.

공개 전에 실패하면 기존 성공본을 유지합니다. 공개 중 응답이 유실되면 다음과 같이 처리합니다.

1. `publish_pending`을 유지하고 새 실행/설정 변경을 막습니다.
2. **최종 저장 결과 확인**을 누릅니다. Target 비밀번호가 필요합니다.
3. 이전 대상 세션의 advisory lock이 풀린 뒤 `_snapshot_runs`의 실행 ID를 조회합니다.
4. 기록이 있으면 SUCCESS로 조정합니다. 없으면 INTERRUPTED/CANCELLED로 조정하여 재시도를 허용합니다.
5. DB 연결이나 잠금 확인이 불가능하면 계속 미확인 상태로 남깁니다. 단순히 heartbeat가 오래됐다는 이유로 실패를 확정하지 않습니다.

완료 파일은 매니페스트의 원본/스키마/기준일/행 제한과 SHA256을 검증한 뒤 재사용합니다. 손상되었거나 스키마가 바뀐 파일은 거부합니다. 해당 실행의 **중간 파일 정리** 후 재시도하면 다시 추출합니다. 다른 실행이 진행 중이면 파일 정리를 막습니다. 성공 시 데이터 파일을 삭제하고 로그/SQLite 이력을 남깁니다. 강제 종료 후 잔여 staging과 부분 파일은 같은 정리 버튼으로 제거합니다.

```sh
.venv/bin/python scripts/benchmark.py --tables 20 --mib-per-table 500 --output benchmark-full.json --reset-disposable-benchmark-dbs
```

벤치마크는 `snapshot_bench_source` / `snapshot_bench_target`만 재생성합니다. 256KiB 반복 BLOB을 사용합니다. 실제 데이터의 타입/인덱스/네트워크/저장장치에 따른 결과는 달라집니다. worker RSS, 중간 파일 크기, 경과 시간, 대상 redo 증가, 공개 구간 시간을 JSON으로 저장합니다. 상세 결과와 미검증 범위는 [VALIDATION.md](VALIDATION.md)에 있습니다.

## 구조

```text
app.py                   Streamlit 연결/작업/실행/복구 화면
snapshot/store.py        SQLite 저장, 원자적 단일 실행 제한, 상태 모델
snapshot/process.py      worker 시작, 프로세스 식별/종료, 로컬 복구/파일 정리
snapshot/worker.py       Streamlit과 독립적인 CLI 진입점
snapshot/engine.py       사전검사 → 추출 → staging → 검증 → 원자 공개
snapshot/db.py           Source SELECT 경로, Target DDL/DML, 스키마/키/타입 검사
snapshot/codec.py        타입 보존 파일, 완료 매니페스트, SHA256
snapshot/secrets.py      OS 자격 증명, 비밀정보 마스킹
```

참고: [Streamlit fragment](https://docs.streamlit.io/develop/api-reference/execution-flow/st.fragment), [PyMySQL 연결 옵션](https://pymysql.readthedocs.io/en/latest/modules/connections.html), [MariaDB KILL](https://mariadb.com/docs/server/reference/sql-statements/administrative-sql-statements/kill).
